# 续期落时刻说明（2026-11-22 锁死）

> 本文档为续期功能落库形态的唯一决策记录。当日锁定，两边不得混用，禁止第三路。

## 选定形态：路线 A —— 同一提交原子写正式占位行

续期（`POST /api/holds/{hold_id}/renew`）在**单个数据库事务、单次 `commit`** 内完成两件事：

1. 更新正式占位行 `holds.expire_at` 为新过期时刻；
2. 写入续期审计 `audit_trail`（`action='hold_renew'`，payload 含旧/新过期时刻）。

任一步失败，事务整体回滚：正式行过期时刻零改、审计不留半截。
本仓为单文件 SQLite（`data/app.db`），两表同库同连接，单事务即满足原子性，
**不引入影子草稿表、不做先草稿后晋升**。

## 明确禁止

- 禁止路线 B（续期影子草稿 → 校验 → 晋升正式行）：本仓不采用，不得新增影子表。
- 禁止任何第三路：只改接口回文、只刷前端倒计时、正式时刻不动一律视为假成功。
- 禁止路线 A 与路线 B 混用。

## 并发：抢档锁，后到只留争用痕

- 续期锁键为 `hold:{hold_id}`（与占位/确认使用的 `slot:{code}` 锁同表不同键）。
- 两人同时续同一占位：先到者拿锁完成续期；后到者 `try_acquire` 失败，
  仅向 `contention_log` 留一条争用痕，接口回 409，**不写任何业务数据**
  （正式行时刻不改、不写续期审计）。

## 五处同源

以下五处必须以库中正式占位行 `holds.expire_at` 为唯一事实源：

1. 续期页倒计时（前端按接口返回的 `expire_at` 计算，不另存时刻）；
2. 占位过期时刻（`/api/holds`、`/api/holds/{id}` 直读正式行）；
3. 续期审计（同一事务落 `audit_trail`，payload 记录 old/new 时刻）；
4. 对账灯（`/api/reconcile` 增加续期同源校验：审计最新续期 new_expire 必须等于正式行时刻）；
5. 档期盘（`/api/dashboard` 续期计数取审计 `hold_renew` 条数）。

只改角标/文案不算过关。
