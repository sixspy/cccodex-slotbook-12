# 续期落时刻说明（2026-11-21 当日锁死）

> 本文件钉死档期预订的续期正确性口径。改动本口径须改日期并重走失败测，禁止当日直改。

## 口径

- **续期必须真改过期时刻**：`holds.expire_at` 在续期事务里前移，绝不只刷新前端倒计时。
- **只走甲路径**：持档锁 → 同一事务内改 `expire_at` + 写 `hold_renew` 审计 → 提交。
  失败则时刻与审计同滚。
- **乙路径不启用**：续期影子原子切换在本仓关闭（`RENEW_SHADOW_ENABLED = False`），
  甲乙两边不得混用。混用按偏航处理。
- **偏航拒写**：续期后时刻未前移、锁内占位态被改写、只刷前端倒计时、
  占位已非占位中或已过期，一律 `409` 拒写，并记审计动作「续期落时刻偏航」，时刻零改。
- **双人续期**：两人同时续同一占位须抢档锁（`slot:<code>`），后到者只留争用痕
  （`contention_log`），不动时刻、不写续期审计。
- **五处同态**：过期时刻、续期结果、占位态、对账、审计必须读到同一个 `expire_at`：
  - 续期结果：`POST /api/holds/renew` 的 `expire_at`
  - 占位态：`GET /api/holds` 的 `expire_at` / `status`
  - 审计：`GET /api/audit?action=hold_renew` 的 `payload.expire_at`
  - 对账：`GET /api/reconcile/<code>` 的 `holds_expire[].expire_at` 与 `holds_ok`
  - 过期时刻：`holds.expire_at` 本身
