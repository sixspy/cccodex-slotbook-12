# 续期账本命运说明（2026-11-22 选定并锁死）

## 选定命运

**就地改写（单一命运）**：续期成功时，在同一事务内

1. 就地更新**原正式有效占位行** `holds.expire_at` 为新过期时刻；
2. 同事务写入一条续期审计 `audit_trail.action='hold_renew'`，payload 记录
   `hold_id / party_key / slot_code / old_expire / new_expire / credential`；
3. 占位主键 `holds.id` 与对外凭证号**保持不变**；
4. 任一环节失败则整笔回滚：过期时刻不变、审计不落，不留半截。

新过期时刻口径（同日锁死）：`base = max(now, 原 expire_at)`，
`new_expire = base + extend_minutes`（默认 30 分钟）。
对外凭证号由占位主键派生（`H-{id:06d}`），续期前后不变，不新增列、不迁库。
续期审计 `payload.old_expire` 记续期前时刻，`new_expire` 记落库时刻。

## 明确禁止

- 不作废原行另开续期新行——本仓**不采用**第二条命运，二者不得混用。
- 不得只改接口回文或只刷前端倒计时。
- 不得出现同一当事人双有效席。
- 不得让倒计时绑定已作废行（本就无作废行）。
- 禁止第三路（影子行、双写、只改文案等）。

## 并发

两人同时续同一占位，须抢 `slot:<code>` 档锁；后到者**只记争用痕**
（`contention_log`），不写占位、不写续期审计、不改过期时刻。

## 同源五处

续期页倒计时、占位详情页倒计时、正式有效占位行、续期审计、对账灯与档期盘
全部只读同一来源：`holds.expire_at` 与同事务的 `hold_renew` 审计。
对账灯新增校验：任一有效占位的最后一次续期审计 `new_expire` 必须等于该行
`expire_at`，否则判分裂（假绿即在此处暴露）。

## 锁死

命运截至 **2026-11-22** 当日锁死，后续实现与测试均按本文件执行。
